# 第三阶段验收记录

第三阶段交付：本地 Markdown/TXT RAG、可追溯来源、确定性退款资格规则、Mock 人工工单，以及资料/工具失败的人工升级策略。

复现命令：

```bash
python scripts/init_demo.py
python -m pytest -q
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

本阶段实际运行了初始化、编译检查和 pytest；pytest 结果为 **21 passed**（运行时另有 FastAPI/Starlette 的第三方弃用警告）。

已覆盖的验收点：

- 初始化实际导入 5 份知识文档与 21 个片段到 SQLite FTS5。
- “这款耳机防水吗？买了多久能退？”通过 `knowledge_qa` 返回真实文档/段落来源；其中含商品说明与退货政策。
- 未检索到资料时明确说无法核实并且不返回伪造来源。
- “这笔订单没发货，能退款吗？”会追问订单号；下一轮订单号由 `refund_eligibility` 用受权订单和 YAML 规则计算资格、原因与规则版本，且文本声明未执行退款。
- 已取消订单按规则给出不可申请；未覆盖的订单状态返回信息不足。
- 明确要求人工会创建可从 SQLite 读取的 `MOCK-TKT-*` 工单，保存摘要、原因、时间和 ID，并明确没有真实人工接线。
- 连续三次未提供订单号或连续两次工具失败会自动升级；模型/工具异常测试仍只返回安全失败，不伪造结果。
- 恶意知识文本只会作为引用数据返回，不会触发人工工单、工具或其他指令执行。

第三阶段结束时尚未完成的是 Streamlit Demo、第二商家替换验证、最终交付文档和端到端验收集合；Streamlit Demo 已在第四阶段完成。
